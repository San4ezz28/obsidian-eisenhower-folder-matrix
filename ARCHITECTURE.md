# Архитектура Eisenhower Folder Matrix (v0.1.3)

## Решение

- **Представление:** `registerMarkdownCodeBlockProcessor('eisenhower-matrix', ...)` преобразует кодовый блок внутри обычной `.md`-заметки в интерактивную матрицу при просмотре Reading view. В исходном Markdown блок остаётся читабельным JSON. Благодаря этому заметку можно перемещать по vault и синхронизировать FIT.
- **Модель:** одна независимая `MatrixConfig` в каждом блоке, содержит `source` (папка или файл), `subtasks`, `inboxFile`, `assignments`, `order`. Различать матрицы позволяет `id`.
- **Выбор источника:** модальное окно использует `FuzzySuggestModal` для выбора существующей папки или файла, а связанные настройки (подпапки, путь для создания) показываются только при источнике-папке. Создание новых задач в папке требует существующего файла; никаких автоматических `Входящие.md`.
- **Источник задач:** Markdown-списки `- [ ]` / `- [x]`, включая вложенные чекбоксы. Сканируются только файлы выбранного источника. Из чтения исключаются fenced code blocks, frontmatter и HTML-комментарии.
- **Идентификаторы:** пока задачей не управляли, она имеет временный ID `(путь, строка, hash)` и обычно находится во Входящих. При первой операции плагин добавляет ей устойчивый Obsidian block ID `^em-...`; затем назначения привязываются к этому ID. Перемещение/переименование исходного файла не меняет ID.
- **Синхронизация:** FIT синхронизирует Markdown-файлы обычным образом; приоритеты лежат в `.md`-матрице, а не в `.obsidian`. Никакой сетевой код/сервер в плагине не используется.
- **Сохранение:** `Vault.process()` обеспечивает консистентное редактирование в рамках одного файла. При обновлении чекбокса/текста используется замена только выбранной физической строки. При изменении приоритета редактируется только кодовый блок заданной матрицы.
- **Отображение:** desktop/tablet CSS grid 2×2; smartphone 4 переключателя секторов + фиксированная область Входящих; мышиная drag-drop + обязательное мобильное меню перемещения.
- **Завершённые:** статус читается из исходного `[x]`; в интерфейсе все выполненные задачи независимо от того, назначались ли они в матрице. Прежнее назначение хранится в конфигурации и восстанавливается при `[ ]`.
- **Подзадачи:** `nested`, `separate`, `hidden`; настройка для каждой матрицы. Завершённые подзадачи всегда отображаются в Сделанном. При `nested` незавершённая подзадача завершённого родителя показывается отдельно, чтобы не потеряться.

## Путь критического действия: перенос карточки

1. Пользователь переносит задачу в квадрант или выбирает пункт меню на телефоне.
2. Если задача без постоянного ID — через `Vault.process` ей присваивается `^em-...` (текст задачи неизменен).
3. Через `Vault.process` JSON в `.md`-матрице обновляет назначения `assignments[id] = quadrant` и массивы `order`.
4. Событие `vault.modify` приводит к пересканированию выбранного источника и обновлению представления.

Прерывание между шагами 2 и 3 оставляет задачу в исходной заметке (с идентификатором), но без нового назначения — она попадёт во Входящие. Это предпочтительнее потери строки.

## Статус тестов

- **Проверены автоматически:** парсинг чекбоксов, пропуск блоков кода и frontmatter, вложенность, отбор по папке, сериализация матрицы, смена квадранта, сохранение и откат состояния, безопасная замена строки CRLF, интеграционный сценарий с имитацией Obsidian Vault.
- **Проверен синтаксис:** bundled `main.js` проходит `node --check`. TypeScript прошёл строгую проверку с локальной тестовой заглушкой сигнатур Obsidian, потому что официальный npm-пакет в среде без доступа к реестру не устанавливался.
- **Остаётся проверить вручную:** реальный API плагина, режим чтения, embed, UX на Windows/Mac/Linux и Android/iOS/iPadOS, мобильное поле выбора, FIT конфликтные обновления и тяжёлые vault.

## Не реализовано в 0.1.0

- Автоматическое трёхстороннее слияние Git-конфликтов; этим занимается FIT/пользователь.
- Редактирование прямо внутри карточки без модального окна.
- Drag & drop пальцем с long-press (работает меню селектора).
- Отображение интерактивной матрицы в исходном режиме редактирования `.md` (пользуйтесь Reading view).
- Дедлайны, повторяющиеся задачи, аналитика и автоназначение важности/срочности.
- Пагинация тысяч карточек и индексирование для очень больших vault.
